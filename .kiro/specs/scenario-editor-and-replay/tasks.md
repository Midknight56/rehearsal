# Implementation Plan

Fleet-owned spec, reviewed by Kiro. Window November 6–18 for tasks 1–14 (work packages R2 and R3, feeding the November 18 gate) and November 17–21 for tasks 15–17 (R7, feeding the November 21 gate). Each module is written in its own worktree (`../Rehearsal-<module>`, branch `fleet/<module>` from `main`) by one agent; a worktree touches only the folders named in its task; wiring into `src/app.tsx`, `src/main.tsx`, `package.json` scripts, `package-lock.json`, `vite.config.ts`, the Vitest and Playwright configuration and the `Scenario` type goes through the integrator named in `docs/fleet.md` on a one-line request in the task's log row. Preconditions on `main` (R0, November 6): `src/domain/scenario.ts` with the plan's `Scenario` type, the zod schema, the validator and the canonical hash; `src/workers/` with the protocol types, their schemas and the adapter; `src/spatial/` with the path function (stubs that pass `npm run verify` are enough until R1); `docs/fleet.md` naming the integrator; `docs/kiro-log.md` from the template. A task is done only after `npm run verify` and, where named, `npm run test:e2e` pass on its branch; the integrator merges only when both pass on the merge result, then requests the Kiro review of task 14 or 17 for that merge. `npm run test:e2e -- <file>` runs one spec (*verify* that the script forwards the argument; otherwise call the Playwright binary with the file path). Two repair passes against the same observed defect, then stop and hand the reproducer to the builder. Kiro review credits for this spec total at most 100; implementation rows in `docs/kiro-log.md` name the fleet agent and its worktree, never Kiro. Nothing in this spec edits `src/domain/`, `src/simulation/`, `src/spatial/`, `src/workers/`, `src/comparison/`, `src/exports/`, `tests/model/`, `tests/comparison/`, `public/examples/harbor-hall/expected.json` or `.kiro/`.
