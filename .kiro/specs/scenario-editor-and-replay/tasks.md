# Implementation Plan

Kiro does every task of this spec (read `_Owner: kiro_`); there is no integrator, fleet, worktree, `docs/fleet.md` or reviewer agent. Work happens in the main checkout on one branch for this spec, `kiro/scenario-editor-and-replay`; commits, when the owner makes or allows them, carry the trailer `Kiro-Task: scenario-editor-and-replay/<n>`. Order, from `.kiro/steering/revision-2026-11-16.md`: tasks 1 to 14, then 16 and 17, before `paired-comparison-and-release` starts. Tasks 18 and 19 call `src/comparison/` and `src/exports/`, which `paired-comparison-and-release` owns and writes in its tasks 1–9, so they run after that spec's task 9 and before its task 14; task 20 runs after the deployment exists (that spec's task 16). The steering file does not name tasks 18–20; this placement is this spec's assumption and the log row of task 18 says so. Task 15 is last and runs only if the owner says there is time, because it needs that spec's tasks 10–13. No task of 1–14, 16 or 17 imports anything from `src/comparison/` or `src/exports/`, and no task other than 15 depends on task 15. Dates in older copies of this file are void.

Every task ends with its `Verify:` line passing and one `docs/kiro-log.md` row the same day (date, surface and model, `scenario-editor-and-replay, task <n>`, files, the Verify command and its printed result, credits, what changed because of a failure). A task that edits a shared file (`package.json`, `package-lock.json`, `tsconfig.json`, `vite.config.ts`, `playwright.config.ts`, `index.html`, `src/main.tsx`, `src/app.tsx`) makes the change itself and names it in that row. No task depends on a hook firing: hooks do not fire in Kiro CLI runs, and every Verify line runs its commands directly. Shell lines in Verify use PowerShell syntax; `npm` and `npx` lines are the same in any shell; Playwright runs headless only. As in `simulation-contract`, task 1 writes the failing tests that are the work list, so `npm run verify` stays red until task 14; each task's own Verify line is its acceptance, and `npm run typecheck` and `npm run test:model` pass after every task. Two repair passes against the same observed defect, then stop and report the reproducer to the owner; a test is never weakened, skipped or marked `fixme` to pass. Nothing in this spec edits `src/domain/`, `src/simulation/`, `src/spatial/`, `src/workers/`, `src/comparison/`, `src/exports/`, `tests/model/`, `tests/comparison/`, the four files `simulation-contract` task 15 writes under `public/examples/harbor-hall/` (`baseline.json`, `plus-one-checkin.json`, `shorter-route.json`, `expected.json`), or `.kiro/` outside `.kiro/specs/scenario-editor-and-replay/`; a defect found there is reported to the owner and recorded in the log row.
