# Revision of 16 November 2026

This file changes how the specs in this repository are carried out. Where this file and a spec, a steering file or a README differ, this file wins.

## Who does the work
- Kiro does every task in every spec. Read `_Owner: fleet` as Kiro.
- Work in the main checkout, one spec at a time, one branch for each spec. Ignore every instruction about separate worktrees, an integrator, and reviews by another agent.
- Ignore every date in a task title. The order below replaces the dates.

## Before the first task
- The spec files have known review findings. They are listed in `plans/review-findings.json`, which is not part of the repository. Apply them first, as the owner's prompt describes. Do not start a task of any spec until every finding marked `blocking` is applied.

## Order of the specs
1. `simulation-contract`, all tasks.
2. `scenario-editor-and-replay`, tasks 1 to 14, then 16 and 17.
3. `paired-comparison-and-release`, tasks 1 to 9, then 14 to 16.
4. Last, and only if the owner says there is time: `paired-comparison-and-release` tasks 10 to 13 and `scenario-editor-and-replay` task 15. These are the extra export files, the printable comparison and the run sheet.

If the tasks of step 4 are not done, the round trip of `scenario-editor-and-replay` task 16 ends at the replay, and no screen offers a print or a run sheet control.

## What must still be true
- The workbook import, the floor plan and the game view all work on one scenario. That is the point of this entry.
- Every hook file uses the standalone format with `version`, `hooks`, `name`, `trigger`, `matcher`, `action` and `timeout`. The trigger names `Stop` and `PostFileSave` are correct for the current Kiro IDE and CLI.
- No version in this repository is 1.0.0 or higher. Where a task says `MODEL_VERSION` 1.0.0, use 0.1.0.
- The film and the pages never show or name a spreadsheet brand. Say "spreadsheet" or "workbook".
- No file in this repository names a prize, a budget or another entry.

## Evidence
- One row in `docs/kiro-log.md` for each finished task, on the same day, with the credits used.
- Walkthroughs with outside organisers are not required. If none happen, the write up says the app was not tested with users.
