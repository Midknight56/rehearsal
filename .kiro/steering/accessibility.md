# Accessibility and UI rules

Rules for everything a judge or organizer sees or imports: `src/ui/**`, `src/replay/**`, `src/imports/**`, `src/storage/**`, `src/ui/styles/tokens.css`, `tests/ui/**` and `tests/e2e/**`. They implement sections 8 and 9 of `plans/rehearsal-implementation-plan.md` (revision 2, 2026-11-03) and Requirements 3–10 of `.kiro/specs/scenario-editor-and-replay/requirements.md`, which carry the exact strings and test names. This file carries the plan's `ui-rules.md` content under this name, including its local-data rules.

## Semantic structure and names
- The arrivals, stations, results, timeline and queue tables are `<table>` with `<caption>`, `<th scope="col">` and labelled inputs; every `button`, `input` and `select` has a non-empty accessible name; every list is named; the `Find attendee` control is a real combobox (`role="combobox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, a `role="listbox"` of `role="option"` items).
- The floor plan and game view wrappers carry `tabindex="0"`, `role="application"`, `aria-label` (`Floor plan`, `Game view`) and `aria-describedby` pointing at visually hidden key help: `Arrow keys move the selected station or the cell cursor, Space toggles a blocked cell, E sets the entrance, X sets the exit, Tab leaves the floor plan.` and `Space plays or pauses, ArrowLeft and ArrowRight step one second, F follows the selected attendee, Escape releases, Tab leaves the game view.` Single-key shortcuts work only while the wrapper has focus.
- Exactly one `role="status"` region (`src/ui/StatusRegion.tsx`), written only through `setStatus`, updated on run completion, cancel, failure, import apply, blocked route, save and save failure, follow changes, move refusals and delete refusals; never per frame (its text is identical across 2,000 ms of playback at 16×); no other `aria-live` or `role="status"` in the rendered app (`tests/ui/status-region.test.tsx`).
- `Undo`, `Redo`, `Simulate` during a run and `Apply import` while the preview has errors stay focusable with `aria-disabled="true"`, never the `disabled` attribute, and the reason appears beside the control and in the status region.

## Keyboard parity for every map action
- Every floor plan action has a form or keyboard equivalent: station cells through `cell_x`/`cell_y` in the stations table and arrow-key nudges of exactly one cell per press while the wrapper has focus; blocked cells through the layout panel's `Blocked cells` list (`Add cell`, `Remove`) and Space on the cell cursor; entrance and exit through `x`/`y` fields and `E`/`X`; grid size through `Columns` and `Rows`. A drag commits once on drop, a nudge commits per press, and each committed edit is one undo entry.
- Game view controls, in this DOM order: `Play`/`Pause` (Space), the `Speed` radio group `1×`, `4×`, `16×`, `Step back` and `Step forward` by exactly 1,000 simulated ms (ArrowLeft, ArrowRight), the scrubber `<input type="range">` labelled `Simulated time` with `step="1000"`, the `mm:ss / mm:ss` readout; `Follow` (`F`, Escape releases, `aria-pressed`) and `Find attendee` beside them.
- Focus is always visible and unobscured: after every Tab the focused element has an `outline-style` other than `none` and `document.elementFromPoint` at its centre returns it or a descendant; no `outline: none`, `outline: 0` or `outline-style: none` anywhere in `src/**/*.css` (`tests/ui/styles.test.ts`). After an action, focus stays on the activated control or the wrapper, or moves to the first changed table after an applied import; it is never lost to `body`.
- `tests/e2e/keyboard-journey.spec.ts` completes import → edit (a station move and a blocked cell) → run → replay (pause, step, find, follow, release) → compare → export with keyboard input only (matrix row 20), and `tests/e2e/reduced-motion.spec.ts` repeats it with reduced motion emulated (row 19). When either fails, fix the product, not the test.

## Reduced motion, colour and the canvas
- Under `prefers-reduced-motion: reduce` or the toolbar `Motion` = `Reduce` toggle (persisted as `motion` in `localStorage['rehearsal.prefs.v1']`): every result loads with the game view paused; `Step back`, `Step forward` and the scrubber come before `Play` in DOM and visual order; `Follow` starts off; `transition: none; animation: none` applies to every element; the camera and the marker drag snap without easing; every control and fact stays available.
- Contrast is computed from `src/ui/styles/tokens.css` by `tests/ui/styles.test.ts` with the WCAG relative-luminance formula: at least 4.5:1 for `--ink` and `--ink-muted` on `--board` and `--card`; at least 3:1 for `--candidate` (cyan), `--baseline` (orange) and `--focus` on `--board`. Change a token only with the recomputed ratios in the log row.
- Colour is never the only cue: baseline elements carry a dashed outline and pattern as well as transparency; the queue line's colour scales with the waiting count and its legend reads `Line colour shows simulated waiting, not measured crowd density.`; stale results carry the text `Stale — rerun`, not a colour.
- The result tables, the person timeline, the queue inspector, `Find attendee`, the scrubber and the step controls work without the canvas: they read `sampleAt`, never the sprites. When PixiJS cannot start, show `The game view could not start in this browser. The timeline and result tables have every number.` with `Retry game view`, keep the results and never clear them. One canvas on the Plan screen; at most 1,000 sprites, with per-station badges and the sentence `Showing 1,000 of <m> attendees as sprites; the others are counted in the badges and every table is complete.` beyond that; the ticker stops while the document is hidden or playback is paused.
- No horizontal page scroll at 1,280 × 720 or 1,024 × 640 CSS px; at 640 × 360 the panels stack vertically with every control reachable by vertical scrolling. No audio anywhere.

## Text nodes, local data, no external resources
- Render every label, ID, message and imported string as a text node: no `dangerouslySetInnerHTML`, `innerHTML` or `insertAdjacentHTML` in `src/ui/**`, `src/replay/**`, `src/imports/**` or `src/storage/**` (`tests/ui/no-html-injection.test.ts`); a station label `<script>alert(1)</script>` appears verbatim in the table, the marker, the timeline, the inspector and the run sheet. The export generators escape printable HTML, CSV exports use `escapeFormulae: true`, and xlsx exports contain no formulas.
- Everything stays in the browser: never fetch a CSV, workbook or scenario from a URL (the app's own `examples/` files are the only fetches); no analytics, external font, script or style, runtime API key or imported JavaScript; every request during the journey is same-origin under `/`, `/assets/` or `/examples/` (`tests/e2e/network.spec.ts`, matrix row 21). Say `no account and nothing uploaded` only after row 21 is recorded on the deployed URL.
- Import only the template columns and sheets: `Arrivals`, `Stations` and the optional `Settings`, matched by exact name; any other sheet is listed under `Not read` and never opened (`tests/imports/xlsx.test.ts` passes a reader that throws on any other name); only counts and operational assumptions enter the scenario, never attendee names, emails, ticket IDs or other personal data; a file above 2,097,152 bytes is refused before parsing; a formula is never evaluated.
- `localStorage['rehearsal.scenarios.v1']` holds only bounded scenario JSON (10 entries) and the comparison summaries, never traces, results or imported files; every read is wrapped so unreadable storage yields an empty list and one message; a failed save shows `Could not save in this browser (<error name>). Export the scenario as JSON to keep it; your edits are still open.` and changes nothing in memory; deleting a saved scenario asks `Delete "<title>" from this browser?` first.
- Write `keyboard accessible`, `works with reduced motion`, `screen-reader usable`, any WCAG statement or any frame rate only after the named test has passed on the submitted build and the reviewer agent has repeated the journey by hand with screenshots under `docs/acceptance/img/`; until then they are targets, and the write-up quotes the test names and the gate report, never this file.
