# Units and determinism

Rules for every file that touches model time, distance, random draws or results: `src/domain/**`, `src/simulation/**`, `src/spatial/**`, `src/workers/**`, `src/comparison/**`, `src/exports/**`, and the display side in `src/replay/**`, `src/imports/**` and `src/ui/**`. They implement sections 5, 6, 7 and 9 of `plans/rehearsal-implementation-plan.md` (revision 2, 2026-11-03) and the `simulation-contract` spec under `.kiro/specs/`, which carries the exact signatures and messages.

## Units
- Display units: minutes for arrival windows, seconds for service, metres for distance, people for counts. Internal time is integer milliseconds (`horizonMs`, `startMs`, `endMs`, every timestamp and duration in results); positions are integer grid cells `[x, y]` (`x` east, `y` south) with an explicit `cellSizeM`, default 0.5.
- Convert once, at the validation boundary, never inside the engine: seconds to milliseconds only through `toDurationMs(seconds) = Math.max(1, Math.round(seconds * 1000))` in `src/domain/validate.ts`; minutes to milliseconds in `src/imports/units.ts`; back to display units in the UI and the export generators. Reject any value whose millisecond form is not a safe integer.
- Distance is `edgeCount * cellSizeM`; walking duration is `Math.ceil(distanceM / walkSpeedMps * 1000)`; a path from a cell to itself is 0 edges, 0 m, 0 ms. Harbor Hall baseline segments are 4,167 / 10,000 / 17,500 ms and the shorter route 4,167 / 3,334 / 7,500 ms; these are hand-calculated and tested directly.
- Every metric is a `MetricValue` with `unit` (`count`, `ms`, `ratio`, `people`, `hours`), `population` (`admitted`, `completedJourney`, `closingWindow`), `n`, `conditioned` and `note`. An undefined mean, total or percentile is `value: null`, rendered `—` (U+2014); never `NaN`, `Infinity`, `undefined` or a fabricated 0. p95 is the ascending-sorted element at index `Math.ceil(0.95 * n) - 1`.
- Name the unit in every label, column header, export cell and log row (`30.0 s`, `100.0%`, `2.67 h`, `4,167 ms`). Staff-hours are `sum(servers) * H / 3,600,000` with no wage or currency.

## No wall clock, no frame time, no hidden random state
- The engine folders `src/domain`, `src/simulation` and `src/spatial` never call `Math.random`, `Date.now`, `performance.now` or `new Date(`, and never replace or reassign `Math.random`; neither they nor `src/workers` import `pixi.js`, `react`, `react-dom`, `src/replay`, `src/ui`, `src/imports`, `src/storage`, `src/comparison` or `src/exports`. `tests/model/purity.test.ts` scans for all of this and fails on any hit. The worker reads an injected `now()` only to throttle `progress` messages, never for model time.
- Every draw comes from `createGenerator(key)` in `src/simulation/random.ts`, the only file that imports `seedrandom`, with the key exactly `${baseSeed}|${replication}|${attendeeId}|${stationId}|service` for a service duration and `${baseSeed}|${replication}|${attendeeId}|arrival` for an arrival. A key never contains the scenario `id`, `revision`, `title`, hash, a cell position, a `servers` value or the processing order, so corresponding attendees receive corresponding draws when a scenario changes (common random inputs, matrix row 9). Constant service, or triangular with `minS === maxS`, takes no draw.
- Triangular `(a, c, b)` by inverse sampling: `a + sqrt(u * (b - a) * (c - a))` when `u ≤ (c - a) / (b - a)`, else `b - sqrt((1 - u) * (b - a) * (b - c))`; `(10, 20, 30)` at `u = 0.125, 0.5, 0.875` gives 15, 20, 25 s before conversion (row 5). Every sampled or constant duration passes through `toDurationMs`, so no service is ever 0 ms.
- Attendee IDs are `${cohortId}#${ordinal}` with the zero-based ordinal padded to four digits (`doors#0000` … `doors#0119`), never an array index after sorting. Even arrivals are `startMs + Math.round((j + 0.5) * (endMs - startMs) / count)` clamped inside `[startMs, endMs - 1]`; uniform arrivals take one draw per attendee, `startMs + Math.floor(u * (endMs - startMs))`. Sort all attendees by `(arrivalMs, attendeeId)` in code-unit order without renumbering.
- Elapsed model time comes only from the event heap. Nothing advances model state from PixiJS's ticker, the follow camera, a scrub, a speed change or a React render: `src/replay/clock.ts` and `src/replay/camera.ts` import nothing from `src/simulation/**` or `src/workers/**`, the replay clock is display state only, and `sampleAt(index, tMs)` in `src/replay/sampler.ts` is a pure function of the trace and the time. The same scenario, seed and replication at 1× with `Follow` off and at 16× with `Follow` on give deep-equal `RunResult`s and byte-identical trace JSON (row 10).
- `simulate(scenario, replication, options)` has no playback, speed, camera or rendering parameter and runs only inside the worker, never on the main thread. The trace stores movement segments (`attendeeId`, `startMs`, `endMs`, `pathId`) and event records, never per-millisecond positions.

## One ordering rule, one version
- Events live in a binary min-heap ordered by `(timeMs, kindPriority, attendeeId, sequence)` with service completion 0, movement arrival 1, external arrival 2, `attendeeId` in code-unit order and `sequence` a per-run counter. At each timestamp apply every equal-time event, including zero-length transfers pushed during the batch, before dispatching any queue; then visit stations in code-unit order of `id` and serve each line in `(queueJoinMs, attendeeId)` order on the lowest-numbered free server. Because service lasts at least 1 ms, a dispatch never creates an event at the current time.
- Admit external arrivals only below `H`; apply a completion at exactly `H`; drain to `H + DRAIN_CAP_MS` (7,200,000 ms). Past the cap set `completion: 'drain-capped'`, list `unfinished` and mark every completion-conditioned metric `conditioned: true` with its note.
- Grid paths: breadth-first search over four-neighbour unblocked in-bounds cells with the neighbours enqueued north, east, south, west and the parent recorded on first discovery, so equal-length ties resolve the same way on every run (row 4). Paths are computed once per layout through the path cache keyed by `stableJson` of the layout (blocked cells sorted by `x` then `y`), the stations' `(id, cell)` pairs sorted by `id` and `walkSpeedMps`; an unreachable pair is the validation issue `UNREACHABLE` naming both endpoints, and `simulate` is never entered with it.
- The canonical hash is the SHA-256 of the canonical JSON of every field except `id`, `revision`, `title` and `notes`, with keys sorted, `stations` and `cohorts` sorted by `id` and `blockedCells` by `x` then `y`. One hash, one seed and one replication give one result. Results whose snapshot hash differs from the current scenario are labelled `Stale — rerun`; a `title` or `notes` change does not change the hash.
- Worker: `runId` strictly increases across `run()` and `cancel()`; any `progress`, `result` or `error` for a non-current `runId` is discarded and counted; `progress` is posted at most 5 times per second; a `cancel` not acknowledged within 250 ms terminates and recreates the worker. Every message is validated with zod on both sides.
- `MODEL_VERSION` in `src/simulation/version.ts` (`0.1.0` at R1 acceptance; no version in this repository is 1.0.0 or higher) changes in the same commit as any change to generator keys, the triangular formula, `toDurationMs`, heap order, batch-then-dispatch, line order, server selection, horizon or cap handling, the BFS tie-break, the distance or duration formulas or any metric definition; `public/examples/harbor-hall/expected.json` is regenerated in that commit (`UPDATE_EXPECTED=1`) and the log row names the semantic that changed. Never regenerate it for any other reason, and never to make a test pass.
- Hand-calculated fixtures (matrix rows 1–11 and the Harbor Hall walking values) are the truth; a disagreement is an engine defect, not a fixture to edit. A fast-check failure is appended to `tests/model/failing-seeds.json` with its seed, path and counterexample and replayed first on every run until the fix is logged in `docs/kiro-log.md`; no property is weakened, no tolerance widened, no test skipped.
